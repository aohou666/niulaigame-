### P1 大招观感不达标（用户明确要求后续修改）

当前实现的核心问题（返工时必须正面处理）：

1. **时长被硬压**：4 秒（96 帧 @24fps）的视频被均匀重采样到原作容器的帧数。很多原作大招只有 9–24 帧（0.4–1 秒），等于把 4 秒动作压成 0.4 秒，观感是"鬼畜快放"。代表作：17（9 帧）、45（11 帧）、65（13 帧）、31（14 帧）、49（12 帧）。
2. **构图/位置是"整屏居中"**：现在把 720×720 全屏帧居中叠在 `battleLayer` 中心，忽略了 `g_skill` 里 `effectQP` 每层的 `offset` / `scaleX` / `timeScale` / `z`。原作大招是**多层分件**（主体 + 地裂 + 文字），现在的做法把其余层全部隐藏，等于丢了原设计的镜头关系与节奏。例：`common_skill_caocao_02` 的 `_1`（z=10000，offset [200,0]，timeScale 1.5）/ `_2`（delay 500）/ `_3`（delay 1000，timeScale 3.5）。
3. **抠像边缘**：本地工作台算法是**二值 alpha**（0/255），没有羽化；青绿/品红辉光在部分角色上有残留（QA 指标 fringe 最高约 69‰，集中在品红幕角色）。放大到战斗尺寸会看到硬边。
4. **绿幕/品红幕里模型自绘的"卡板"**：已用"同色系第二取色"处理（最严重的外星牛 812‰ → 44‰），但这是启发式，某些角色仍可能残留色块或把同色系内容啃掉。
5. **只接了 83/85**：6 刀盾牛、18 肘击牛在原作里找不到对应大招容器（`keys_86.json` 里本来 `frames=0`、`skill_model` 为空），这两条视频**连素材都没生成**（`local_game/assets/street/ultimate/006`、`018` 不存在）。
6. **有 22 个角色的"原作帧数"取错了**（这条最容易被忽略，但直接决定观感）：`tools/street_ultimate_mat.py plan` 用"该角色在大招键表里最长的容器"当主层，结果 22/83 与 `_ult86.json` 里记录的 spec 不一致，例如
   - 2 老八：取了 2 帧的 `common_skill_simayi_02_1`（spec 41 帧）→ 4 秒视频被压成 0.08 秒；
   - 63 麻将牛爷：3 帧（spec 32）；11 阿伟：12 帧（spec 57）；22 机器牛：14 帧（spec 81）；31 丧尸牛：14 帧（spec 57）；82 杰哥：12 帧（spec 42）；
   - 54 驱鬼道长：取到另一个模型 `common_skill_zhangjiao_baguazhen`（110 帧，spec 是 `common_skill_zhangjiao_02` 41 帧）；
   - 83 金龙：62 帧（spec 91）。
   - 完整清单：`agent-handoff-20261104/映射不一致.csv`；每角色的实际帧数/时长/压缩倍率见 `agent-handoff-20261104/角色时长表.csv`（含 `speedVsSource`，越大越像快放）。
   - 返工时应改为：以 `_ult86.json` 的 `model`+`frames`+`fps` 为权威，在该角色的键集合里按动画时长匹配容器；匹配不到再看 `g_skill` 里 `effectQP` 中 `z=10000` 的那层，或去掉 `_N` 后缀的 base 模型。

**建议的返工方向（供参考，不是让照抄）**：

- 先决定"时长策略"：是严格贴原作时长（就要接受快放，或只取视频里最像"爆发"的一段），还是改技能表现节奏（工程量大、要过玩法验收）。**这一步必须和用户确认后再批量做**，不要自己假设。
- **先把 22 个映射不一致的角色修对**（见上面第 6 点），再谈节奏；否则"快放"里有一半是映射错误造成的假象。
- 构图改为**按原作层的 offset/scale/timeScale/z 合成**，或至少保留 `effectQP` 的偏移/缩放；不要无条件整屏居中。
- 抠图加 2–6px 边缘羽化 + 去溢色；绿幕色系内容改用另一种幕色重生成（现有 10 条品红幕就是按这个思路）；必要时逐条手调阈值/擦除。
- 建立"逐角色对比"：原版大招录屏 vs 新版，同一时间点并排截图，人工过一遍再批量。

## 2. 这次实际做了什么（已完成部分）

### 2.1 抠图与重定时

- 源：`outputs/street-reskin/ultimate-keys-86/videos/`（85 条，720×720、96 帧、24fps、无音轨；75 条绿幕、10 条品红幕）。
- 脚本：`tools/street_ultimate_mat.py`
  - 抠像算法**移植自**本地绿幕导帧工作台 `outputs/green portable smoke/Greenscreen-Frame-Studio-Eraser-Portable/app.js`：边框 16px 取样（greenish 过滤 + 中位数）→ RGB 距离 ≤ 64 → 通用绿规则 → 二值 alpha。
  - 额外补了：同色系"暗卡板"清除（HSV 同色相 + 低亮度）、同色系主色二次取色（解决模型自绘的亮/暗卡板）、去溢色（按幕色族只处理对应通道）。
  - 内容窗口 = 有 alpha 覆盖的帧区间（自动丢掉 0.4s 纯幕开场/收尾），再按原作容器帧数均匀重采样。
  - 逐帧裁到 alpha bbox，保存 WebP q90（`alpha_quality=100`）+ 每帧偏移框。
- 产物：`local_game/assets/street/ultimate/<001..094>/f###.webp` + `meta.json`；**83 个角色 / 2914 帧 / 67.1 MB**（同内容 PNG 约 1.1 GB）。
- QA：`tools/street_ultimate_qa.py` 出 `outputs/street-reskin/ultimate-verify/qa-matte.json`；抽检图 `contact-*.png`。

### 2.2 数据表

- `tools/build_street_ultimate_data.py` → `local_game/street-ultimate-data.js`
  - 每角色：目录、canvas、frames、fps、`keys`（唯一归属的触发键，159 个）、`allKeys`（含共享键，169 个）、逐帧文件名 + bbox。
  - 共享键（如 `common_skill_tianfeng_02` 被 6 个角色共用）走"施法者判定"，不能靠键名触发。

### 2.3 运行时

- `local_game/street-ultimate.js`（包装层，ES5）：
  - 包装 `DBEffect.prototype.trigger`：命中某角色大招容器时 `effect.visible=false`，在 `effect.parent`（通常是 720×1280 的 effLayer）中心新建 Sprite 播放新帧序列。
  - 帧率 = **原作容器 fps × effect.timeScale**，帧数 = 原作容器帧数 → 时长与技能时钟一致。
  - 预取 10 帧、落后 6 帧释放；启动前等 4 帧就绪（最多 700ms）；画面卡顿时用"停表"而不是丢帧。
  - 包装 `FightTools.prototype.handleEffectQP / handleEffectSrc / handleEffectTar` 记录施法者，用于共享键角色。
  - 异常一律回退原效果。
- 接入：`local_game/index_bh_lite3zbtest_andr.html` 里 `<script src="street-ultimate-data.js?v=20261104-ultimate-1">` + `street-ultimate.js`（在 `street-fx-dispatch.js` 之后）。

### 2.4 APK

- 打包脚本：`tools/package-full-apk.py`
  - 复用旧 debug shell（`android_offline_shell/app/build/outputs/apk/debug/app-debug.apk` 的 `classes*.dex` + 二进制 manifest + `resources.arsc`），替换整棵 `assets/`。
  - **所有资产必须 STORED**：`AssetHttpServer` 用 `AssetManager.openFd()`，压缩条目会 404 白屏。
  - **ZIP 路径镜像 local_game**：`assets/<相对 local_game 的路径>`；街景资产因此是 `assets/assets/street/...`。
  - `zipalign` 无法处理 ≥2 GiB 的包，4 字节对齐由脚本用 `0xD935` 扩展字段自己写；`resources.arsc` 必须 STORED 且对齐。
  - `--slim`（默认）：删 781.7 MB 引擎取不到的内容（1026 个未注册街景 FX 容器 433.2 MB；890 个有 `_ez` 孪生的 HD 特效容器 348.5 MB），再把街景角色/皮肤 WebP 以 q92 重压、大 PNG 无损重压（约再省 110 MB）。
  - `--full`：不删不压，2.20 GB。
- 签名：`outputs/apk-build/offline.p12`（PKCS12，别名 `offlinekey`，密码 `offline`），用 SDK build-tools 36.1.0 的 `apksigner.jar` + `.tools/jre17-tuna` 的 java。**同一密钥才能覆盖升级，别丢**。
- 产物：
  - `outputs/原创角色换皮-大招版-精简.apk` — 1.21 GiB（用户手机上打不开的就是这版）
  - `outputs/原创角色换皮-大招版-完整.apk` — 2.05 GiB（未在真机验证过，用于 A/B 对照）
- 包内 versionName 仍是 `0.19.0`（继承自旧 shell），改它需要重编二进制 manifest。
